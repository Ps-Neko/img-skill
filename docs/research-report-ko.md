## 1. 조사 개요

이 조사의 목적은 특정 문장을 흉내 내는 것이 아니라, 이 계정에서 반복적으로 관찰되는 프롬프트의 구성 순서와 시각 제어 방식을 재사용 가능한 생성 시스템으로 바꾸는 것이다.

조사는 세 층으로 진행했다.

1. X의 `from:xiaoxiaodong01` 최신 검색을 날짜 구간으로 나누어 계정 활동과 프롬프트 관련 게시물을 선별했다.
2. 초기·중기·최근 구간이 한쪽으로 치우치지 않도록 개별 게시물 원문 페이지를 정독하고 본문 코드 블록, 본문 뒤 프롬프트, 이미지 ALT, 보이는 답글에서 프롬프트를 추출했다.

**핵심 결론:** 이 계정의 강점은 화려한 형용사보다 먼저 하나의 강한 시각 장치—찢어진 틈, 거대한 글자 마스크, 길게 늘어진 그림자, 화면 상·하 분할, 중앙 투명 용기 등—를 정하고, 그 장치를 구도·여백·재질·색 역할·타이포그래피·금지 조건으로 확장하는 데 있다. 반면 프롬프트가 길어질수록 반복 수식과 충돌 가능성이 커지고, 후기 13개가 하나의 골격에 크게 의존한다는 한계가 있다.

| 색 역할 | 시선과 감정의 우선순위 | 보통 | 바탕/주/보조/강조색, 면적과 명도 | 주제에서 파생하되 역할은 고정 | 서로 충돌하는 팔레트 이름 나열 | 87.0%, 정확값 0% |
| 빛·카메라 | 현실감·움직임·초점 | 선택 | 빛 방향/부드러움, 필요한 시점만 | 제품·영화형에서 활성화 | 이유 없는 렌즈 이름 | 빛 75.9%, 카메라 31.5% |
| 타이포·정보 | 글자를 구조로 통합 | 유형별 필수 | 제목 크기, 자간, 위치, 정보 층수 | 지배 장치와 가리거나 이어지게 함 | 긴 문장을 장식처럼 추가 | 88.9% |
| 출력 계약 | 수량·비율·독립성 | 예 | 1장/각 사진별, 3:4 등 | 일반형은 끝, 변환형은 앞 | 서로 다른 비율 두 개 | 77.8% |
| 금지 조건 | 예상 실패를 차단 | 예 | 3~6개의 관찰 가능한 오류 | 긍정 지시와 모순 없어야 함 | 막연한 “나쁘지 않게” | 75.9% |

### 8.3 유형별 순서 변형

**일반 포스터**  
`목적·주제 → 첫눈 장치 → 큰 면과 구도 → 피사체/배경 → 재질 → 색 → 여백 → 글자 → 분위기 → 금지 → 비율`

**제품 광고**  
`사용처 → 제품과 판매 포인트 → 주·보조 제품 배치 → 배경 구조 → 재질·반사 → 조명 → 색 대비 → 글자/행동 정보 → 비율 → 금지`

**PPT·정보 디자인**  
`콘텐츠 목적 → 정보 계층 → 그리드/페이지 시스템 → 제목·본문·데이터 크기 → 이미지 앵커 → 색과 투사 가독성 → 일관성 → 비율`

**후기 사진 변환**  
`각 입력별 독립 출력·비율 → 상단 원본 보존 → 하단 핵심 형태 추출 → 재질 재구성 → 여백·관계 → 사진에서 색 추출 → 글자 통합 → 분위기 → 왜곡·템플릿 금지`

## 9. 단계별 생성 알고리즘

### 9.1 입력

최소 입력은 다음과 같다.

```text
만들 이미지 / 사용 목적 / 핵심 피사체 / 원하는 스타일 / 분위기
/ 색상 / 화면 비율 / 반드시 포함 / 제외 / 사용할 모델
```

### 9.2 처리 절차

1. **아이디어를 사실과 취향으로 분리한다.** 피사체·제품명·문구처럼 반드시 정확해야 하는 것과, 따뜻함·고급스러움 같은 추상 취향을 나눈다.
2. **부족한 정보만 질문한다.** 목적, 피사체, 첫눈의 초점, 비율, 필수/금지가 없으면 최대 3개의 묶음 질문을 한다.
3. **이미지 유형을 고른다.** 포스터/편집, 제품 광고, PPT/정보, 인물/패션, 공간, 일러스트/3D, 영화적 장면 중 주 유형 하나를 선택한다.
4. **유형 블록을 불러온다.** 카메라는 영화·제품·인물에, 정보 계층은 PPT·인포그래픽에, 보존 블록은 입력 이미지 변환에만 활성화한다.
5. **중요도를 세 단계로 나눈다.** P0은 목적·피사체·필수 문구, P1은 지배 장치·구도·색 역할, P2는 재질·빛·보조 소품이다.
6. **충돌을 제거한다.** “극사실+평면 일러스트”는 한 영역을 사진, 다른 영역을 일러스트로 분리하거나 하나를 버린다. “미니멀+정보 10개”는 정보형으로 재분류한다.
7. **추상어를 관찰 가능한 시각어로 바꾼다.** “고급”을 그대로 두지 않고 여백, 정보 계층, 제한 색, 재질 정밀도, 장식 억제로 바꾼다.
8. **한 가지 지배 장치를 선택한다.** 첫눈에 무엇이 보이는지 한 문장으로 답할 수 없으면 프롬프트를 다시 줄인다.
9. **실제 관찰 순서로 배열한다.** 일반형은 목적→주제→장치→구도→재질/색→글자→금지→출력, 사진 변환형은 출력 계약을 맨 앞으로 옮긴다.
10. **출력·금지 조건을 붙인다.** 비율, 수량, 각 입력별 독립 출력, 왜곡·과밀·템플릿감 금지를 추가한다.
11. **중복 수식어를 제거한다.** 같은 의미의 “깨끗함/맑음/청량함”은 하나의 색·배경 규칙으로 합친다.
12. **품질검사를 실행한다.** 100점 체크리스트, 충돌 검사, 유형 필수 블록, 모델 문법의 근거 여부를 확인한다.

### 9.3 추상어 변환 사전

### 9.4 충돌 해결 규칙

- `원본 보존 + 강한 스타일 변형` → 보존 영역과 변형 영역을 분리한다.
- `미니멀 + 많은 정보` → 정보 우선이면 그리드형, 분위기 우선이면 정보 3~5개로 줄인다.
- `사진적 현실감 + 판화/종이` → 피사체 형태·정체성은 유지하고 표면 렌더만 변환한다.
- `밝고 맑음 + 어둡고 묵직함` → 하나를 큰 바탕, 다른 하나를 작은 앵커로 역할 분리한다.
- `큰 제목 + 피사체 전체 노출` → 제목을 뒤 구조물 또는 마스크로 두고 피사체와 부분 가림 관계를 만든다.
- `텍스트 없음 + 문구 필수` → 제목 한 줄만 허용하거나 텍스트 없음 조건을 폐기한다.
- `정확한 브랜드색 + 주제에서 자동 추출` → 브랜드색을 고정 강조색, 자동 추출색을 보조색으로 제한한다.

### 9.5 출력 형식

알고리즘은 매번 다음을 반환한다.

1. 짧은 버전: 1~3문장
2. 상세 버전: 선택된 모든 블록
3. 부정 조건: 모델이 별도 칸을 지원할 때만 분리, 아니면 상세 버전 끝에 자연어로 통합
4. 수정 변수: 주제, 지배 장치, 비율, 색 역할, 재질, 정보량
5. 적용 패턴: 어떤 계정 근거를 적용했는지 3개 이하
6. 품질 점수와 감점 사유

## 10. 알고리즘 의사코드

아래의 `[R#]`는 이 연구의 증거 규칙이다.

- R1 구도 95.5%(훈련 44개 기준)
- R2 재질 90.9%
- R3 색 88.6%
- R4 여백 93.2%
- R5 타이포그래피 93.2%
- R6 금지 조건 81.8%
- R7 출력 조건 84.1%
- R8 카메라 29.5%: 선택
- R9 사조·디자이너 27.3%: 선택
- R10 자연어 문단 53/54: 기본
- R11 모델 명령 6.8%: 선택
- R12 후기 사진 분할은 13개지만 1계열: 하위 문법

```text
FUNCTION collect_user_input(raw_input):
    input.image_idea       <- raw_input.image_idea
    input.use_case         <- raw_input.use_case
    input.subject          <- raw_input.subject
    input.style            <- raw_input.style
    input.mood             <- raw_input.mood
    input.colors           <- raw_input.colors
    input.aspect_ratio     <- raw_input.aspect_ratio
    input.must_include     <- raw_input.must_include
    input.must_exclude     <- raw_input.must_exclude
    input.model            <- raw_input.model
    RETURN input

FUNCTION classify_image_type(input):
    IF input.use_case contains presentation OR many information points:
        RETURN PRESENTATION_INFO
    IF input.use_case contains product sale OR menu OR launch:
        RETURN PRODUCT_AD
    IF input.subject is person AND use_case is portrait/fashion:
        RETURN PORTRAIT_FASHION
    IF input.subject is building/interior/space:
        RETURN ARCHITECTURE_SPACE
    IF input.style contains illustration/3D/craft:
        RETURN ILLUSTRATION_3D
    IF input requests sequence, action change, or cinematic moment:
        RETURN CINEMATIC_SEQUENCE
    RETURN POSTER_EDITORIAL

FUNCTION detect_missing_information(input, type):
    missing <- EMPTY_LIST
    FOR field IN [use_case, subject, aspect_ratio]:
        IF field is empty: ADD field TO missing
    IF first_glance_focus cannot be inferred: ADD first_glance_focus
    IF type is PRESENTATION_INFO AND information_points empty: ADD information_points
    IF input image exists AND preservation_rule empty: ADD preservation_rule
    RETURN missing

FUNCTION generate_followup_questions(missing):
    GROUP missing into at most 3 plain-language questions
    RETURN questions

FUNCTION concretize_visual_language(input):
    visual <- input
    visual.mood_rules <- map_abstract_mood_to(color, light, spacing, edge, material)
    visual.quality_rules <- replace "premium/beautiful/cool" with
        hierarchy + whitespace + controlled palette + material precision
    visual.first_glance_mechanism <- choose ONE drawable mechanism
    RETURN visual

FUNCTION select_prompt_blocks(type, visual):
    blocks <- [PURPOSE, SUBJECT, FIRST_GLANCE_MECHANISM, COMPOSITION]  // R1
    ADD BACKGROUND, MATERIAL, COLOR, WHITESPACE                       // R2-R4
    IF type uses text or information: ADD TYPOGRAPHY                 // R5
    IF type in [PRODUCT_AD, PORTRAIT_FASHION, CINEMATIC_SEQUENCE]:
        ADD LIGHTING, CAMERA                                         // R8 is conditional
    IF input image exists: ADD PRESERVATION
    ADD OUTPUT_CONTRACT, NEGATIVE_CONSTRAINTS                        // R6-R7
    IF named reference is necessary and non-conflicting: ADD REFERENCE // R9 optional
    RETURN blocks

FUNCTION determine_block_order(type, blocks):
    IF input image exists AND transformation requested:
        RETURN [OUTPUT_CONTRACT, PRESERVATION, TRANSFORMATION,
                COMPOSITION, COLOR, MATERIAL, TYPOGRAPHY,
                MOOD, NEGATIVE_CONSTRAINTS]                          // R12
    IF type is PRESENTATION_INFO:
        RETURN [PURPOSE, INFORMATION_HIERARCHY, GRID, TYPOGRAPHY,
                IMAGE_ANCHOR, COLOR, READABILITY, OUTPUT_CONTRACT]
    RETURN [PURPOSE, SUBJECT, FIRST_GLANCE_MECHANISM, COMPOSITION,
            BACKGROUND, MATERIAL, COLOR, WHITESPACE, LIGHTING,
            TYPOGRAPHY, MOOD, NEGATIVE_CONSTRAINTS, OUTPUT_CONTRACT]

FUNCTION apply_model_syntax(blocks, model):
    IF model is labeled GPT2/GPT-Image2 in the user's workflow:
        USE connected natural-language paragraphs                  // R10
        OPTIONALLY prefix "@创建图片" only if user requests it      // R11
    ELSE:
        USE model-neutral natural language
        FLAG "specific syntax not verified from this account"
    RETURN blocks

FUNCTION detect_conflicts(blocks):
    conflicts <- find pairs such as
        minimal vs high-density,
        preserve vs globally transform,
        photoreal vs flat everywhere,
        no-text vs required copy,
        multiple aspect ratios
    RETURN conflicts

FUNCTION resolve_conflicts(blocks, conflicts):
    FOR conflict IN conflicts:
        preserve P0 instruction
        split roles/regions if compatible
        otherwise remove lower-priority instruction
    RETURN blocks

FUNCTION remove_redundancy(blocks):
    MERGE synonyms that control the same property
    KEEP one adjective plus one observable visual rule
    REMOVE named references that add no new control
    RETURN blocks

FUNCTION generate_negative_conditions(type, predicted_failures):
    negatives <- top 3 to 6 observable failures
    IF input image exists: ADD stretch, distortion, identity change
    IF poster: ADD clutter, template feel, meaningless decoration
    IF material style: ADD cheap aging, muddy color, fake texture
    RETURN negatives

FUNCTION assemble_prompt(ordered_blocks):
    short_prompt <- compress P0 + first_glance + composition + output
    detailed_prompt <- connect all nonempty blocks causally
    RETURN short_prompt, detailed_prompt

FUNCTION quality_check(prompt, type, model):
    score <- score_with_100_point_rubric(prompt)
    IF subject unclear OR contradiction exists OR output conflict exists:
        status <- FAIL
    ELSE IF score < 80:
        status <- REVISE
    ELSE:
        status <- PASS
    RETURN score, status, deductions

FUNCTION format_results(short, detailed, negatives, variables, evidence, qc):
    RETURN {
        short_prompt,
        detailed_prompt,
        negative_prompt_if_needed,
        editable_variables,
        applied_patterns_and_reasons,
        quality_score_and_deductions
    }

FUNCTION build_image_prompt(raw_input):
    input <- collect_user_input(raw_input)
    type <- classify_image_type(input)
    missing <- detect_missing_information(input, type)
    IF missing not empty: ASK generate_followup_questions(missing)
    visual <- concretize_visual_language(input)
    blocks <- select_prompt_blocks(type, visual)
    blocks <- determine_block_order(type, blocks)
    blocks <- apply_model_syntax(blocks, input.model)
    conflicts <- detect_conflicts(blocks)
    blocks <- resolve_conflicts(blocks, conflicts)
    blocks <- remove_redundancy(blocks)
    negatives <- generate_negative_conditions(type, predicted_failures)
    short, detailed <- assemble_prompt(blocks + negatives)
    qc <- quality_check(detailed, type, input.model)
    RETURN format_results(short, detailed, negatives, editable_variables, evidence, qc)
```

9. **`GPT2` 표기를 공식 모델 사양으로 확대 해석하지 않는다.** 다른 모델의 `--ar`, 샘플러, 가중치 문법을 이 계정 근거 없이 추가하지 않는다.
10. **빈도와 독립 증거를 구분한다.** 13개 변형이 한 계열이면 신뢰도를 13배로 올리지 않는다.
11. **결과 이미지를 반드시 검수한다.** 이 보고서는 텍스트 구조를 검증했지, 동일 조건의 이미지 성공률을 측정하지 않았다.

## 19. 최종 결론

**[관찰]** 54개 고유 프롬프트에서 가장 안정적으로 반복된 것은 핵심 주제, 구도, 여백, 재질, 색 역할, 타이포그래피, 감정, 금지 조건이었다. 렌즈·정확한 색값·모델 전용 파라미터는 중심이 아니었다.

**[해석]** 이 계정의 실제 문법은 “형용사를 많이 쓰는 법”이 아니라 다음 네 가지다.

1. 주제를 한 가지 강한 시각 장치로 변환한다.
2. 그 장치의 면적·위치·크롭·여백으로 화면을 설계한다.
3. 분위기를 색 역할·재질 흔적·빛·글자 계층으로 물리화한다.
4. 예상 실패를 자연어 금지 조건으로 닫는다.

**[설계안]** 따라서 재사용 시스템의 최소 공식은 다음이다.

```text
목적과 주제
→ 첫눈의 장치 하나
→ 큰 면과 읽는 순서
→ 재질·색·빛으로 분위기 구체화
→ 글자와 정보 밀도 통합
→ 출력 계약
→ 관찰 가능한 실패 금지
```

신뢰도는 포스터·편집 디자인에 높음, 제품 광고·PPT·영화적 분할에 중간, 인물·패션·건축·3D 전용 문법에는 낮음이다. 주제 마스킹 검증은 81.1/100이었지만 엄격한 맹검도 이미지 품질 실험도 아니므로, 이 알고리즘은 **검증된 최종 법칙**이 아니라 **현재 확인 가능한 계정 자료에 가장 잘 맞는 재사용 가능한 초안**으로 보는 것이 정확하다.

가장 공정한 평가는 다음과 같다.

> 이 계정은 시각 편집 구조를 언어로 해체하고 재조립하는 능력이 강하고, 여러 주제에 재사용할 수 있는 프롬프트 모듈을 일관되게 만든다. 다만 장문 반복, 후기 템플릿 의존, 모델별 기술 문법과 통제 실험의 부족 때문에 모든 이미지 생성 영역의 보편적 전문가라고 단정할 수는 없다.
